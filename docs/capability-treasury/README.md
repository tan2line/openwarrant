# Capability Treasury

**An InnerLearn · fCAIGO portfolio home for reusable intellectual assets and the offerings they support.**

Capability Treasury collects the methods, software, evidence packs, content and delivery systems that can be reused across InnerLearn offerings. It connects each asset to its source, maturity, evidence, rights information and practical commercial use.

The portfolio label `InnerLearn · fCAIGO` preserves the user's supplied wording. No expansion of fCAIGO is assumed.

## Structure

| Level | Name | Role |
|---|---|---|
| Portfolio umbrella | InnerLearn · fCAIGO | User-designated portfolio home |
| IP collection | Capability Treasury | Catalog and packaging of reusable assets |
| Capability family | OpenWarrant Eval | Workflow evaluation and evidence preparation |
| Paid offering | Workflow Evaluation Sprint | A bounded engagement supporting one accountable decision |
| Reusable assets | Code, scenarios, rubrics, reviewer desk, receipts, articles | Inputs that support delivery, demonstration and learning |

First registered offering: [CT-OFF-001: OpenWarrant Eval / Workflow Evaluation Sprint](offerings/CT-OFF-001-openwarrant-eval.md).

## What belongs in the Treasury

- Software libraries, applications and adapters.
- Methods, protocols, rubrics and diagnostic frameworks.
- Scenario packs, test data and reusable evidence formats.
- Articles, teaching materials and demonstration narratives.
- Productized engagements and delivery playbooks.
- Proposed capabilities with explicit dependencies and completion criteria.

Registration records portfolio placement. It does not establish a legal assignment, exclusive ownership, valuation or a new license. Existing public OpenWarrant repository materials retain their Apache-2.0 terms. Customer-specific materials require their own provenance and agreed reuse terms before they enter a reusable collection.

## Register once, reuse deliberately

Use the [asset-card template](asset-card-template.md) and [machine-readable catalog](catalog.json). Each item receives a stable ID, asset type, maturity state, source path, steward, rights note, evidence basis, supported offerings and next action. Relationships show which assets power an offering and which proposed assets depend on future work.

The initial catalog contains only assets verified in the OpenWarrant package. It is not a completed inventory of every InnerLearn project. Broader portfolio intake should resolve canonical sources before adding items, so a remembered idea is never represented as a shipped product.

## Reuse and improvement cycle

An offering uses a defined version of its supporting assets. Delivery findings can suggest a better rubric, new test case or clearer explanation. Review those improvements and their reuse permissions, version the accepted changes, and link later offerings to the improved asset. Keep customer evidence separate from public demonstration material.

## Operating responsibilities

Andrew Plummer is the proposed portfolio steward for this starter. Every engagement still needs a delivery lead, appropriately qualified reviewers, an adjudicator and a customer-designated decision owner. These roles are not assigned to external collaborators by this catalog.

The Treasury is initially a catalog and packaging convention in GitHub. It is not yet a deployed portfolio application, licensing portal or subscription service.
